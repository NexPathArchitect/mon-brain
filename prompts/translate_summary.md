# 翻译 + 总结 + 整理模式

处理下面的素材（以法语口语转写为主），依次完成总结、整理；不要写整段外文总结。

1. **总结**：提炼核心要点和链路，按主题分组；突出这则素材最有价值的点以及为什么。
2. **整理**：输出结构化 Markdown，含标题、要点分组、待办清单。
3. **对照**：正文用中文；关键术语按语言要求附外文对照；命令、链接、原始术语保留原形，不要翻译命令。
4. **误写还原**：按上方静态对照表还原转写误差；「待确认」项标注存疑，不要硬猜。
5. **只依据素材，不编造**；模型自己的推论单独标注；区分 **素材事实 / 他人观点 / 你的推测**。
6. **纠正句优先**：素材里出现教师纠正学生的说法（「不是 X，而是 Y」「不需要 X」「不是六部，只是三部」这类否定—更正结构），必须保留更正后的结论，单独成条，且**不得**把 X 和 Y 并列成同一层级的要求。这类句子是全篇信息密度最高的地方。
7. **数字必须带单位**：所有数字连同原文单位照抄；`points` 是「分」、`minutes` 是「分钟」，二者**不得互换**，也不得把「10 points」写成「10 分钟」。单位在原文里含糊时，写成「（单位存疑）」而不是补一个猜测值。
8. **术语表唯一**：全篇只出一张术语表，放在文末；只收素材里**真实出现**的词，人名、机构名、软件名不进术语表；素材里没有的术语一律不补，拿不准写「（待确认）」。
9. **不重复**：同一内容只写一次。不要在用要点列完之后再贴一个代码块把同样的内容重列一遍。
10. **存疑清单**：文末术语表之前，用一小节列出「听不清 / 原文不足以判定 / 需回听」的条目；这些不要塞进待办清单，也不要用推测填补。
