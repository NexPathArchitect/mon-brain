# mon_brain —— 本地 Ollama 个人整理 / 翻译总结 / 复盘工具

**语言 / Languages / Langues**：[中文](README.md) · [English](README.en.md) · [Français](README.fr.md) · [📖 在线文档 / Docs / Documentation](https://nexpatharchitect.github.io/mon-brain/)

跑在本机 Ollama 上的命令行小工具：读素材 → 超长自动分片合并 → 按模式套提示词 → 调本地模型 → 输出 Markdown 到 `sortie/`。
数据不出本机；不依赖老师工坊项目的代码，只复用了同样的 Ollama 调用思路。

## 三种模式与默认模型

| 模式 `--mode` | 用途 | 默认模型 | 思考链 |
|---|---|---|---|
| `organize` | 客观提取、结构化整理 | `qwen2.5:latest` | 剥离 |
| `translate_summary` | 总结 + 整理（法/英转写素材为主） | `gemma3:12b` | 剥离 |
| `recap` | 深度复盘 + 提问/问法评估 + 自检 | `qwen3:14b` | **保留** |

模型可用 `--model` 手动覆盖。

## 算力配置（本机最优档，2026-11-23 实测）

显卡 RTX 5070 Ti Laptop 12 GB、内存 31 GB。Ollama 已按下表配好（用户级环境变量，重启 Ollama 生效），配置脚本见 `configure_ollama.ps1`：

| 变量 | 值 | 作用 |
|---|---|---|
| `OLLAMA_FLASH_ATTENTION` | `1` | Flash Attention，提速 + 省显存 |
| `OLLAMA_KV_CACHE_TYPE` | `q8_0` | KV Cache 半精度→8bit，显存减半、质量几乎无损 |
| `OLLAMA_NUM_PARALLEL` | `1` | 串行跑长文，避免并行把 KV Cache 撑爆 |
| `OLLAMA_MAX_LOADED_MODELS` | `1` | 只留一个模型，防止两个 12B 抢显存 |
| `OLLAMA_KEEP_ALIVE` | `30m` | 半小时不卸载，避免每次都付 15–20 秒冷加载 |

验证方式（都是实测通过的状态）：`ollama ps` 显示 `100% GPU`；日志里 `offloaded 49/49 layers to GPU`、`flash_attn = enabled`、`K (q8_0) / V (q8_0)`。

**上下文窗口**：默认 `8192`（`MB_NUM_CTX` 可覆盖）。实测 `gemma3:12b` 热态下单次输出：`8192` → 27.6 秒 / 8.7 GB 显存；`12288` → 34.3 秒 / 8.9 GB 显存（仍 100% GPU）。**结论：8192 是甜点**，12288 慢 24%，只有在单份素材必须一次塞进去时才用。

**混合流水线（`--map-model`）**：分片摘要用快模型、终稿用精模型。28 694 字符法语转写实测：纯 `gemma3:12b` 344 秒；混合（`qwen2.5:latest` 分片 + `gemma3:12b` 终稿）**106 秒**，约 3.2 倍。
- 分片阶段有 **token 硬上限** `MAP_PREDICT=420`（约 800 字符/片），光靠提示词约束小模型不可靠（实测它会写到 2 000+ 字符/片，把速度优势吃光）。
- **二级压缩固定用精模型**：弱模型会把输入原样吐回，导致压缩停滞、整篇被误判为"超预算"而拒稿。
- Web 界面新增三档算力预设：**极速**（`qwen2.5:latest` 单模型）/ **均衡**（分片 `qwen2.5` + 终稿 `gemma3:12b`）/ **高质**（纯 `gemma3:12b`，数字与结构最准但最慢）。
- 出稿 YAML 头部会记录 `map_model`，回看可知这份是怎么跑的。

## 原理与架构：长素材为什么反而更快

处理一条 28 694 字符的法语课转写，纯用 `gemma3:12b` 跑要 344 秒，混合流水线只要 106 秒。原因不是"多开几个 agent 并行"，而是**把每一步的工作量压小、把贵的那一步只做一次**。

流水线（`mon_brain.py` 里的 `process_one`）：

```text
素材（>5000 字符）
   │  split_text: 3500 字符/片，相邻重叠 200 字符（防止切断句子与上下文）
   ▼
[map] 每片单独调用 → 粗提炼，num_predict=420（约 800 字符上限）
      └ 顺序执行，不是并行：Ollama 设为 NUM_PARALLEL=1，片上并行会抢显存
   ▼
合并稿（各片要点拼接）
   │  若仍超过单次预算 → reduce_to_budget: 用精模型层级再压缩，最多 3 轮，压缩停滞即停
   ▼
[reduce] 合并稿 ≤ 预算（约 8700 字符）
   ▼
[final] 系统指令 + 任务提示词 + 语言要求 + 你的意图 + 合并稿 → 终稿
```

**预算怎么来**：`NUM_CTX=8192` 减去输出预留，再减去指令预留（约 700 token），按 `CHAR_PER_TOKEN=2` 估算，得约 8700 字符的安全上限。超过就先分片；分片后仍超，才动第二级压缩。

**为什么变快**（三条，缺一不可）：

1. **贵模型只写一次**。`gemma3:12b` 每 token 约为 `qwen2.5:latest` 的 2.6 倍耗时，所以让它只做"终稿"这一件事，粗活交给小模型。
2. **输出被 token 上限钉死**。生成时间是输出长度的线性函数：每片限 420 token，9 片合计约 3 800 token，而不是让模型自由发挥写出两三万字。
3. **避免了"大模型反复压缩"的路**。单次塞 28k 会直接超上下文，只能靠 `gemma3` 一轮轮压缩，而每次压缩本身又是全量生成——纯 `gemma3` 那 344 秒大部分花在这里。混合方案的分片后合并稿只有 7 587 字符，一次就进终稿，压缩轮数为 0。

**它和"多个子 agent"的区别**：分片是固定流水线（map-reduce），同一套提示词、无状态、互相不通话、不做决策，只是把一次超长的请求切成若干次短请求；子 agent 是各自带目标、带工具、会自己规划下一步的独立执行者。前者能省时间是因为**总量变小**，不是因为有并行度。

**相关常量**（`mon_brain.py` 顶部）：`SPLIT_THRESHOLD=5000`、`CHUNK_SIZE=3500`、`CHUNK_OVERLAP=200`、`MAP_PREDICT=420`、`NUM_CTX=8192`、`MAX_REDUCE_ROUNDS=3`、`CHAR_PER_TOKEN=2`。

## 输出语言策略

**正文始终用中文**；`--lang` 只控制关键术语/段落的**对照语言**，不会生成整段外文总结。文末术语表固定为 **中文 / English / Français** 三语。

| `--lang` | 含义 |
|---|---|
| `zh` | 仅中文正文，不附段落对照（默认） |
| `en` | 中文正文 + 关键术语/段落英语对照 |
| `fr` | 中文正文 + 关键术语/段落法语对照 |
| `bilingual` | 中文正文 + 英语、法语对照 |
| `fr-zh` | `bilingual` 的旧别名，兼容保留 |

## 图形界面（Web UI）

除命令行外，也可以起一个本地网页界面（127.0.0.1，数据仍不出本机）：

```powershell
cd C:\path\to\mon_brain
.\.venv\Scripts\python.exe app_web.py
# 自动打开 http://127.0.0.1:5000
```

- 界面默认**英语**，右上角可切**中文 / 法语**（方便给不懂中文的老师演示）。
- **页面自带说明**：顶部「使用须知」可展开六条（模式区别、三档实测耗时、分片模型是什么、调试信息是什么、意图怎么填、复盘如何追问）；每个控件旁的 `?` 徽标悬停或点击会弹出当前语言的解释。模式下拉直接写成 `translate_summary · 翻译总结 · Résumé`，不用记英文名。
- **完全离线可用**：Tailwind 已本地化到 `static\tailwind.js`（页面从 `/static/tailwind.js` 加载，不再请求 CDN）；新机器上若缺文件，跑 `tools\fetch_vendor.ps1` 一次即可。断网、无外网教室都能正常显示。
- **`/docs` 说明页**：顶部「说明 / Docs」会在新标签打开 `http://127.0.0.1:5000/docs`，直接把本 README 渲染成网页（可切中文 / English / Français），原理、架构、参数表、实测数据都在里面，适合用完后回来复习。右上角可返回工作台。
- **处理过程可见**：点开始后结果区上方会实时滚动进度日志（读取素材 → 分片 i/n → 调用模型 → 保存），不再是一块"假死"的静止画面。
- **调试视图**：勾选「显示调试信息」，出稿后会附带实际使用的系统指令、任务提示词、语言要求、分片数、上下文字符预算、素材字符数等，便于对照排查。
- **多会话切换**：「复盘会话」区列出 `sessions\` 里所有会话，点 open 直接载入历史对话气泡，可接着追问。
- **提示词模板可编辑**：「提示词模板」区可下拉选择 `prompts\*.md`，直接编辑并保存回原文件，不用再开编辑器。
- **输出两档**：
  - `中文总结 + 对照`（默认）：中文正文 + 所选对照语言 + 三语术语表；
  - `跟随素材语言整篇`：整篇用素材语言输出（法语素材出法语、英语素材出英语），不切中文。
- 支持：多选文件上传、模式/对照语言/模型选择、多文件合并勾选、全新开始开关、复盘对话式追问、历史稿件查看与下载。
- 复盘模式有一个可选「意图 / 你的提问」输入框（对应命令行 `--intent`）；留空则只复盘素材本身。
- 连不上本地 Ollama 时，结果区会用红色醒目提示去启动 Ollama。
- 网页上传的文件临时存在 `sources\_upload\`，超过 24 小时的临时目录会在下次上传时自动清理；生成的正式稿件仍落在 `sortie\`。

## 命令示例

在本目录打开 PowerShell：

```powershell
# 直接用 venv 的 Python（无需激活）
$py = ".\.venv\Scripts\python.exe"

# 1) 单个文件：总结 + 整理（默认模式，中文正文）
& $py mon_brain.py "C:\path\to\notes\lecture.txt" --lang bilingual

# 2) 整个文件夹逐个生成 md
& $py mon_brain.py "C:\path\to\notes" --mode organize

# 3) 多文件合并成一篇（文件间共享上下文）
& $py mon_brain.py "C:\path\to\notes" --mode organize --merge

# 4) 复盘模式（保留思考链，评估问法 + 自检），并进入追问循环
& $py mon_brain.py sources\test_recap.txt --mode recap --interactive

# 5) 续接上次复盘会话（多轮追问）
& $py mon_brain.py sources\test_recap.txt --mode recap --continue

# 6) 手动指定模型；--fresh 表示不沿用上次草稿，从头生成
& $py mon_brain.py sources\xxx.docx --mode recap --model deepseek-r1:8b --fresh

# 7) 查看有哪些提示词文件
& $py mon_brain.py --list-prompts
```

## 命令行参数

| 参数 | 作用 |
|---|---|
| `--mode` | `organize` / `translate_summary` / `recap`，默认 `translate_summary` |
| `--model` | 覆盖该模式的默认模型 |
| `--lang` | `zh` / `en` / `fr` / `bilingual`（见上表） |
| `--merge` | 文件夹输入时，把所有文件汇总成一篇，而不是逐篇出稿 |
| `--fresh` | 关闭增量更新：不读取上次草稿，从头生成 |
| `--interactive` | 复盘模式：首稿生成后进入追问 Q&A 循环 |
| `--intent` | 仅复盘模式：你本轮的提问 / 想得到什么，供第二步评估提问质量；留空则只复盘素材本身 |
| `--continue` | 读取 `sessions\` 里上次的复盘会话，继续多轮追问 |
| `--list-prompts` | 列出 `prompts\` 下的提示词后退出 |
| `--map-model` | 混合流水线：分片摘要 / 二次压缩用这个快模型，终稿仍用 `--model` 的精模型 |

## 数字保真自检

终稿生成后会做一次机械校对：把素材里的"数字 + 单位"（如 `40%`、`10 points`、`3部`、`6篇`）和"三位数以上/反复出现的独立数字"（如课程号 `102`）抽出来，逐个确认是否出现在终稿里。

- 有缺失：CLI 打印 `⚠ 数字保真自检…缺 X 项`，Web 结果区上方弹**琥珀色黄条**，列出缺失项；md 头部记 `fidelity_missing: N`。
- 全在：CLI 打印 `✓ 数字保真自检通过`，Web 不打扰。
- 这是启发式提醒，不是证明：它能抓"数字被丢掉/被改写"，但判断不了"数字挂错了条件"。所以黄条出现时请人工看一眼，别直接打印。

## 改前端后必跑：页面自检

`app_web.py` 的界面是一整段内联 JS，一个括号写错就会让**整段脚本不执行**——表现是"语言按钮没反应、档位按钮没反应、上传也没反应"，很像前端事件没绑，实际是语法错误。改完必须先跑：

```powershell
.\.venv\Scripts\python.exe tools\check_page.py
```

它做三件确定性检查：

| 检查 | 抓什么 |
|---|---|
| JS 语法（调用 `node --check`） | 缺括号、逗号、引号等，直接给出行号 |
| 三语词典覆盖 | `data-i18n` 用到的键在 en/zh/fr 里是否齐全（缺键会显示原始键名，看着像切语言失效） |
| `getElementById` 目标 | 脚本里引用的 id 是否真的存在于 HTML（拼错就会绑到 null） |

退出码 0 才算通过。这个脚本做过反向验证：故意删一个 `);`，它会失败并指出第 87 行。

## 静态误写对照表（corrections.txt）

语音转写里的常见错拼（如 `Olama → Ollama`、`Lama → Llama`、`LocalRoss → localhost`）写在 `corrections.txt`，脚本按素材内容命中后才注入提示词（剥离标点、忽略大小写、按词边界匹配），素材里没出现的条目不会塞进提示词，避免污染输出。

- 格式：`错拼 => 正确词  # 备注`；`#` 开头为注释。
- `[uncertain]` 区段为**待确认**项，输出时会标注存疑，不会当成定论。
- 你可以随时往里增补自己遇到的高频错拼。

## 增量更新

再次处理同一素材（同模式、同文件名）时，脚本会自动在 `sortie\` 找最新一版旧稿，作为「上一版草稿」注入，在其基础上补充、修订，而不是从头再来。加 `--fresh` 可关闭此行为。旧稿永远不会被覆盖。

## 多文件合并与会话记忆

- **合并模式 `--merge`**：逐文件先出要点摘要，前序文件的结论作为后续文件的背景上下文，最后融合成一篇总稿；输出头部 `source` 记录全部来源文件。
- **复盘会话**：复盘的首轮问答会存入 `sessions\<素材名>.json`；`--interactive` 可在首稿后继续追问，`--continue` 下次接着上次的历史聊。追问记录会追加到同一篇 md。

## 输出规则

- 文件名：`日期_模式_素材名.md`；同名已存在自动加序号，**不覆盖原稿**。
- md 头部 YAML 元信息：来源文件、模式、模型、语言、日期；复盘稿附会话文件名。
- **长素材**：超过约 5000 字符（或超过单次上下文预算）自动分片，逐片出要点摘要再合并成一篇；合并稿若仍超预算，会自动再压缩（最多 3 轮），仍放不下才提示你拆分处理，不硬截断。
- 合并后素材仍过长时，会给出警告，提示拆成多次处理。
- **复盘模式**：拆两段调用——先出素材复盘，再出问法评估 + 自检；思考链单独成节；外层多余 Markdown 围栏会被自动剥掉。

## 当前限制（后续批次再做）

1. **复盘重复段落（已修）**：模型常在第二段把三大部分整篇重抄一遍。已加 `strip_repeated_sections`：按标题文本去重，遇到重复标题就截断（实测 4 836 → 2 501 字符）；同时 prompts/recap.md 明确「每部分只写一次」。
2. **段落对照执行不到位**：本地 12B 模型对「关键段落附外文对照」的遵循不稳定，多数时候只在术语表给出三语对照；正文段落对照可能缺失。
3. **生成长度上限**：单次输出上限约 2048–2560 token，极长回答结尾仍可能不完整。
4. **扫描版 PDF 读不了**：图片型 PDF 需要 OCR（llava / easyocr），尚未接入。
5. **模型能力上限**：本地 7B–12B 模型在法语地道度、长文逻辑、术语英译上不如云端大模型；输出需本人终审，存疑项不要当定论。
6. 待做：源码项目解析、扫描 PDF OCR、分段续写长回答；网页结果区目前以纯文本展示 Markdown，富文本渲染留待后续。

## 常见报错

- **连不上 Ollama / Connection refused**：确认 Ollama 已启动（任务栏图标，或另开终端 `ollama serve`）。
- **model not found**：模型名和 `ollama list` 里不一致；用 `--model` 改成列表里的精确名字。
- **PDF 读不出文字**：大概率是扫描图片 PDF，当前版本不支持 OCR。
- **中文/法语乱码**：脚本已强制 UTF-8；如控制台仍乱码，确认用的是 `.venv` 里的 Python。
